### Organization-Scoped Patterns

1. **All survey operations are organization-scoped** - Every protected procedure uses `context.activeOrganization.id` to filter by the current organization

2. **Survey ownership model**:
   - Surveys have both `userId` (creator) and `organizationId` (owning org)
   - Access control is based on `organizationId` membership, not `userId`
   - The `verifySurveyAccess()` helper pattern is used across routers to validate survey belongs to organization

3. **Role-based access**:
   - **Member** (`organizationProcedure`): Can view surveys, questions, responses, analytics
   - **Admin** (`adminProcedure`): Can create/update/delete surveys, questions, logic rules, responses
   - **Owner** (`ownerProcedure`): Can delete surveys (destructive operations)

4. **Public access**:
   - `survey.getBySlug` - Public read for published surveys
   - `response.getSurveyForRunner` - Public read for survey runner
   - `response.submit` - Public write for submitting responses

**Structure:**
- Uses `SurveyBuilder` component with 3 tabs: Build, Preview, Share

- Builder header shows breadcrumb: "Surveys / {title}" with status badge

### 3. Survey Sharing/Distribution (`apps/web/src/components/distribution/`)

**DistributionPanel (`distribution-panel.tsx`):**
- Generates public survey URL: `{baseUrl}/s/{slug}`
- Provides three sharing methods:

**a) Public URL (`copyable-field.tsx`):**
- Simple copy-to-clipboard field
- URL format: `/s/{slug}`

**b) QR Code (`qr-code-generator.tsx`):**
- Generates QR code from survey URL
- Downloadable as PNG
- Filename: `{slug}-qr-code.png`

**c) Embed Codes (`embed-code-preview.tsx`):**
- Three embed options:
  - **Iframe**: Standard iframe embed
  - **Popup**: Script tag that loads `/embed/{slug}.js`
  - **Button**: Styled HTML button linking to survey

### 4. URL Structure for Survey Access

**Public respondent URLs:**
- Survey page: `/s/{slug}` → `apps/web/src/app/s/[slug]/page.tsx`
- Embed mode: `/s/{slug}?embed=true`
- Completion page: `/s/{slug}/complete`

**Management URLs (authenticated):**
- Survey list: `/surveys`
- Survey builder: `/surveys/{surveyId}`
- Analytics: `/surveys/{surveyId}/analytics`
- New survey: `/surveys/new`

### 5. Organization Context in UI

**App Header (`apps/web/src/components/app-header/app-header.tsx`):**
- Shows `OrganizationSwitcher` dropdown (when user has organizations)
- Displays current active organization name
- Allows switching between organizations

**Organization Switcher (`apps/web/src/components/organization-switcher.tsx`):**
- Uses Better Auth's organization plugin
- Fetches organizations via `authClient.organization.list()`
- Switches active org via `authClient.organization.setActive()`
- Refreshes page on switch to update data

### Key Observations for Multi-Organization Support:

1. **Survey URLs are flat** - Currently use only `/s/{slug}` without organization context
2. **Slug uniqueness** - Must be globally unique since URLs don't include org
3. **Organization filtering** - Happens on backend via activeOrganizationId in session
4. **Share tab visibility** - Only shown when survey is published (good UX)
5. **No org indicator in public survey** - Respondents don't see which organization owns the survey
