# Landing Page Theme Overhaul Plan

## Context

The landing page components have been implemented but use hardcoded Tailwind color classes (`violet-*`, `neutral-*`, `zinc-*`, `white`, etc.) instead of shadcn's CSS variable-based theming system. This plan focuses on migrating all hardcoded colors to use semantic theme variables, enabling:

1. **Dark mode support** - Components automatically adapt to theme changes
2. **Consistency** - Colors come from a single source of truth
3. **Maintainability** - Theme changes propagate automatically
4. **Flexibility** - Easy to rebrand by changing CSS variables

## Implementation Steps

### Phase 1: Add Missing Semantic Variables

**File:** `apps/web/src/index.css`

Add semantic color variables for status indicators:

```css
:root {
  /* Existing variables... */

  /* Success (green) */
  --success: oklch(0.60 0.18 145);
  --success-foreground: oklch(0.98 0 0);

  /* Warning (orange/amber) */
  --warning: oklch(0.70 0.18 60);
  --warning-foreground: oklch(0.15 0 0);

  /* Info (blue) */
  --info: oklch(0.55 0.18 250);
  --info-foreground: oklch(0.98 0 0);
}

.dark {
  /* Dark mode variants */
  --success: oklch(0.65 0.18 145);
  --success-foreground: oklch(0.15 0 0);

  --warning: oklch(0.75 0.18 60);
  --warning-foreground: oklch(0.15 0 0);

  --info: oklch(0.60 0.18 250);
  --info-foreground: oklch(0.15 0 0);
}
```

Add Tailwind theme mappings in `@theme inline`:

```css
@theme inline {
  /* Existing mappings... */
  --color-success: var(--success);
  --color-success-foreground: var(--success-foreground);
  --color-warning: var(--warning);
  --color-warning-foreground: var(--warning-foreground);
  --color-info: var(--info);
  --color-info-foreground: var(--info-foreground);
}
```

### Phase 2: Fix Mesh Gradient

**File:** `apps/web/src/index.css`

The mesh gradient uses hardcoded colors. Replace with theme variables:

```css
.mesh-gradient {
  background-color: hsl(var(--background));
  background-image:
    radial-gradient(at 0% 0%, hsla(var(--primary), 0.05) 0, transparent 50%),
    radial-gradient(at 100% 0%, hsla(var(--primary), 0.08) 0, transparent 50%),
    radial-gradient(at 100% 100%, hsla(var(--primary), 0.1) 0, transparent 50%),
    radial-gradient(at 0% 100%, hsla(var(--primary), 0.06) 0, transparent 50%);
}
```

*Note: Using oklch variables directly in radial-gradient requires careful handling. May need to create CSS variables for gradient stops.*

## Special Cases

### Avatar/Badge Accent Colors

The mockup components use various accent colors (pink, blue, green, orange, purple) for visual interest.

**Decision:** Keep avatar colors hardcoded. These are decorative illustrations, not semantic UI elements. They provide visual variety and don't need theme support.

### Dark Sections (Footer, Pricing Business tier)

Some sections use dark backgrounds (`bg-neutral-950`) regardless of theme. Options:

1. **Always dark** - Keep these sections dark in both themes
2. **Theme-aware** - Use `bg-card` with proper dark mode styling
3. **CSS variable** - Create `--surface-inverted` for intentional inversions

**Recommendation:** Use theme variables but accept that dark sections will look different in light mode. Consider using `bg-primary` for featured elements.

### Hardcoded SVG Colors

Some components use inline SVG with hardcoded stroke colors:

```tsx
stroke="#8b5cf6"  // violet-500
stroke="#eee"     // neutral-200
```

**Solution:** Use `stroke="currentColor"` with a text color class, or use CSS variables via `style`:

```tsx
<circle style={{ stroke: "hsl(var(--primary))" }} />
```
