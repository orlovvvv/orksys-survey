# Phase 4: Analytics & Insights Implementation Plan

## Context

This plan implements Phase 4 of the survey platform, adding comprehensive analytics dashboard and AI-powered insights. The current system has:
- Survey builder and runner fully functional (Phases 1-3 complete)
- Basic `response.getStats` endpoint returning `{ total, complete, partial }`
- Minimal dashboard showing only API status and subscription info
- No chart library or analytics visualization components

The goal is to enable analysts to view survey results at a glance and leverage AI to find patterns in text responses.

---

## Implementation Overview

### New Dependencies
```bash
pnpm add recharts --filter @orksys-survey/web    # Chart library
pnpm add @tanstack/react-table --filter @orksys-survey/web  # Response table
pnpm add openai --filter @orksys-survey/api     # Groq (OpenAI-compatible) client
```

### Environment Variables (for AI Insights)
```
GROQ_API_KEY=<your-groq-api-key>
GROQ_MODEL=llama-3.3-70b-versatile  # or mixtral-8x7b-32768, llama-3.1-8b-instant
```

> Note: Groq uses OpenAI-compatible API. The service layer will use `openai` SDK with `baseURL: "https://api.groq.com/openai/v1"`.

## 4. AI Integration Strategy

### 4.1 LLM Service Layer

**File:** `packages/api/src/services/llm.ts` (NEW)

- Use OpenAI SDK with Groq's compatible endpoint (`baseURL: "https://api.groq.com/openai/v1"`)
- Structured output with Zod schemas for consistent response parsing
- Models: `llama-3.3-70b-versatile` (recommended) or `mixtral-8x7b-32768`
- Synchronous processing with loading states in UI
- Error handling with retries for rate limits

### 4.2 Caching Strategy

| Data Type | TTL | Storage |
|-----------|-----|---------|
| Summary stats | 5 min | `analyticsSnapshot` table |
| Question analytics | 10 min | `analyticsSnapshot` table |
| AI analysis | 24 hours | `aiAnalysis` table |
| Trends | 30 min | `analyticsSnapshot` table |

### 4.3 Processing Pattern

**Synchronous with UI loading states:**
1. User opens AI Insights tab
2. Frontend shows loading spinner
3. API checks cache → if expired, calls Groq API
4. Returns results (typically 1-3 seconds)
5. Cache stored for subsequent requests

For surveys with >500 text responses, consider batching the LLM calls or showing progressive results.
